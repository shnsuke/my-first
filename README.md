# デッドリフト・トレーニングトラッカー

Claude(AI)を介さずに、①目標重量・目標期限の設定 → ②現在の1RM記録 →
③トレーニング記録 → ④次回トレーニング内容の提案、のサイクルを自力で回して
目標達成を目指すための自己完結型Webアプリです。

## 設計方針

- **提案ロジックは全てルールベース(決定論的アルゴリズム)。** 毎回AIに聞く
  必要はなく、ブラウザ内のJavaScriptだけで④の提案を生成します。
- **サーバー不要。** データは端末のブラウザ`localStorage`に保存されるため、
  `index.html`を開くだけ(あるいは静的ホスティング)で動きます。
- **ロジックとUIを分離。** `js/suggestion.js`は純粋関数のみで構成し、
  DOM に依存しないため Node の標準テストランナーで単体テストできます。

## 使い方

```bash
# ローカルで動かす場合(モジュール読み込みのため file:// ではなくHTTP経由推奨)
npx serve .
# または
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000` を開き、タブを ①→②→③→④ の順に使います。
一度環境を用意すれば、以降は完全にオフラインでも動作します。

## データモデル

```
Goal            { targetWeight, targetDate }
OneRMRecord     { id, date, weight, reps, note }
TrainingLog     { id, date, sessionType, sets: [{weight, reps, rpe}], note }
```

`OneRMRecord`は回数=1なら実測1RM、2回以上ならEpley式
(`1RM = 重量 × (1 + 回数/30)`)で推定1RMを計算します。
`TrainingLog`の各セットも同様に、直近21日以内の最良の推定値を
「現在の1RM」として採用します(`getCurrentE1RM`)。

## ④ 次回提案アルゴリズム(`js/suggestion.js`)

1. **現在の1RM推定**: 直近21日以内の実測/推定1RMの最大値。
2. **目標までの軌道評価**(`computeTrajectory`): 目標期限までの残り週数と
   必要重量から、週あたりに必要な伸び率を計算。安全とされる伸び率
   (週1.0kg)を超える場合は「危険水準」と警告し、期限見直しを促す。
3. **セッション種別の循環**(`getNextSessionType`): ボリューム→
   インテンシティ→テクニックの3種を繰り返し、前回テストから28日以上
   経過、または目標期限が10日以内に迫った場合は1RM再テストを挟む。
4. **負荷の自動調整**(`prescribeSession`): 前回同種セッションの平均RPEを
   見て、目標RPEより低ければ負荷を上げ、高ければ下げるオートレギュレー
   ションを行い、2.5kg刻みに丸めて提示する。

この4ステップにより②③④のサイクルが毎回自動的に更新され、①の目標に
向けた提案が完全にアプリ内で完結します。

## テスト

```bash
npm test
```

`tests/suggestion.test.js` が提案エンジンの主要ロジック(Epley推定、
現在1RM算出、軌道評価、セッション循環、オートレギュレーション)を検証します。

## ディレクトリ構成

```
index.html          UI本体(タブ切り替え)
css/style.css        スタイル
js/storage.js         localStorage永続化
js/suggestion.js       提案エンジン(純粋関数、テスト対象)
js/chart.js           1RM推移の折れ線グラフ描画(依存ライブラリなし)
js/app.js             UIとロジックの結線
tests/suggestion.test.js  提案エンジンの単体テスト
```

## バックアップ

「履歴・グラフ」タブからJSONエクスポート/インポートが可能です。
localStorageはブラウザ・端末に紐づくため、機種変更やキャッシュクリア前に
エクスポートしておくことを推奨します。
